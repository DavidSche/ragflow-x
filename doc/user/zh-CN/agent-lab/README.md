# 智能体练习包

配套《智能体上手指南》（`doc/user/zh-CN/ragflow-x-agent-guide.docx`）第 4、5、6、9 章。
包里只有数据和模板，不含任何特定环境的 id、账号或地址——**换到任何一套 RAGFlow-X 都能用**，
你只需要把自己的模型 id 和数据集 id 填进去。

```
agent-lab/
├── README.md                       本文件
├── dsl/01-echo.json                场景一：Begin → Message（回显，不调用模型）
├── dsl/02-knowledge-qa.json        场景二：Begin → Knowledge → Generate → Answer
├── dsl/03-data-pipeline.json       场景四：File → Parser → TokenChunker → Tokenizer（数据管道）
├── corpus/差旅报销制度.md            语料（含条款号与金额表）
├── corpus/信息安全事件报告制度.md     语料（含分级与时限表）
├── corpus/供应商准入管理办法.md       语料（含评分区间表）
├── prompts.md                      16 条提问与期望观察点
└── worksheet.md                    练习记录表（复制一份再填）
```

## 开始之前

1. 你在当前工作区的角色是 member 或 admin（viewer 只能看，点发送会 403）。
2. 有一个可用的模型，能拿到它的 `llm_id`（模型管理页里复制）。
3. 有一个已解析、chunk 数大于 0 的数据集。

## 练习一：十分钟跑通一次对话（对应指南第 4 章）

1. 复制 `dsl/01-echo.json` 全文。
2. 智能体列表 → 「导入 JSON」→ 粘贴 → 标题填「回显练习助手」→ 导入。
3. 进入画布，确认工具条显示「节点 2 / 连线 1」。
4. 保存，然后发布。
5. 会话页签新建一个会话（如「上手体验」），切到「对话运行」，选中它，发一句「你好」。

**通过标准**：回答是「收到：你好」，且中途点停止后那一行不会停在「生成中」。
这一步不需要模型，所以跑不通一定是权限、会话或网络的问题——变量最少。

## 练习二：做一个制度问答助手（对应指南第 5 章）

1. 新建数据集「制度库-练习」，上传 `corpus/` 下三份 Markdown，解析，确认 chunk 数 > 0，
   并在数据集的检索测试里用「住宿标准」试一句，能看到片段再继续。
2. 复制 `dsl/02-knowledge-qa.json`，用「导入 JSON」建成「制度问答助手」。
3. 选中 Knowledge 节点，把「知识库」勾成上一步的数据集；「空结果回复」保留默认那句人话。
4. 选中 Generate 节点，把 `llm_id` 填成你自己的模型 id。
5. 保存 → 发布 → 开会话，按 `prompts.md` 场景二的 12 条提问跑一轮，结果填进 `worksheet.md`。

**通过标准**：
- 第 1、3 条给出同一组金额，并指出出自《差旅与报销管理办法》第三条；
- 第 4 条（年会抽奖）明说资料里没有，不编条款号；
- 第 5 条（写文案）拒绝或拉回制度范围。

三个里有一个不达标，按指南 5.8 节的表定位：先看检索测试，再动阈值与 `top_n`，最后才改提示词。

## 练习三：不导入模板，自己搭（对应指南第 6 章）

1. 新建一个空智能体（分类选对话型 agent_canvas）。
2. 从算子库依次拖入 Begin → Knowledge → Generate → Answer，连线成一条主链。
3. 故意连一条回到 Begin 的线，看界面拒绝的原因码（应是 `begin_target`）。
4. 选中 Generate，只改提示词里一句，点「应用属性」，然后保存。
5. 发布，打开版本页签的差异对比：**应该只有 1 条 `form.prompt` 变更**。
   如果冒出一串 `form.temperature`、`form.top_p`，说明写回逻辑退化了，记下来报给维护者。
6. 切到 JSON 页签，导出这份 DSL；把 `kb_ids`、`llm_id`、`rerank_id` 清空后另存，
   这才是一份可以发给别人的模板。

## 练习四：把文档变成文本块（对应指南第 9 章）

这一条故意和前面三条不一样：它搭出来的东西**不能对话**，也**没有会话页签**。

1. 新建智能体，分类选「数据管道」，标题「管道练习」。
2. 用「导入 JSON」导入 `dsl/03-data-pipeline.json`，确认画布上是
   File → Parser → TokenChunker → Tokenizer 四个节点、三条连线。
3. 选中 TokenChunker，把分块大小改成 512、分隔符补上 `。；！？`，点「应用属性」。
4. 保存 → 发布，记下版本列表里那一行的时间。
5. 让数据集指向这条管道。这一步在「解析策略」里做：解析模式选管道、选中刚发布的版本，并对**已上传的文档**
   再设一次（文档级不会自动跟随数据集级）。数据集页面目前只有结果、没有选择入口，
   所以如果你不是管理员，把智能体标题与版本 id 给管理员配一次即可。
   配好后，数据集页面的「知识编译治理」里这条文档不应再显示「未绑定 Ingestion Pipeline」。
6. 重新解析，等状态变成已完成，记下 chunk 数；在检索测试里跑 `prompts.md` 场景四的 13–16 条。
7. 最后回到「管道练习」的页面，确认没有「会话」「对话运行」页签——
   如果手上有接口工具，给它发一句对话，会得到 400 与错误码 `40162`。

**通过标准**：
- 解析完成且 chunk 数大于 0，第一块从标题开始、没有把页眉页脚切进正文；
- 第 13、14 条能在检索测试里命中正确段落；
- 界面上看不到会话入口，接口发消息被 40162 拒绝。

改了画布记得重新发布：数据集钉的是**版本**，不是画布本身。只改画布不重发，解析跑的还是旧快照。

## 练习五：对账（对应指南第 10 章）

1. 在「对话运行」里跑一句，记住助手消息上的 `request_id`。
2. 打开用量明细，按 `request_id` 找到那一条，确认 `model=agent`、`scenario=agent`、tokens 不为 0。
3. 打开审计，按资源筛选，确认这一串动作都在链上：创建、保存、发布、会话创建、补全。
4. 换一个 viewer 账号打开同一个智能体，点发送，确认被 403 拒绝。

**通过标准**：用量能按 `request_id` 对上，审计条目能按资源归因，viewer 被服务端拒绝。

## 清理

练完把「回显练习助手」「制度问答助手」「管道练习」和「制度库-练习」删掉，
再回列表确认总数回到开始时的数字。删智能体不会自动清掉引擎侧的会话记录，
所以删之前先把会话删掉，审计里才会留下完整的动作链。

## 常见问题

| 现象 | 原因 | 办法 |
| --- | --- | --- |
| 导入后一运行就 50289 | 模板里 `llm_id` / `kb_ids` 是空的 | 按练习二第 3、4 步填自己的 |
| 回答恒为「资料里没有找到相关规定」 | 数据集没解析，或 chunk 数为 0 | 回数据集重新解析 |
| 回答对但从不给条款号 | 提示词第 2 条没生效 | 改提示词，别动检索参数 |
| 答非所问、混进不相干条款 | 阈值太低、`top_n` 太大 | 先把阈值从 0.2 提到 0.3 试一轮 |
| 点发送 403 | 角色是 viewer | 换 member / admin 账号 |
| 管道解析后 chunk 数没变 | 只绑了数据集级，文档还按内置解析器跑 | 文档级再设一次，或用解析策略统一下发 |
| 给管道画布发消息报 40162 | 它不是对话入口，这是设计 | 去数据集里解析文档 |
| 找不到刚建的会话 | 打开的是另一个智能体或另一个工作区 | 核对智能体标题 |

## 语料说明

`corpus/` 下三份制度是**虚构的示例文本**，只用于练习检索与引用，不构成任何制度依据。
它们刻意写成「条款号明确、含表格、有时限数字」的样子，是为了让「回答是否正确、是否可归因」可判定。
换成你自己公司的真实制度同样可以，但记得脱敏后再放进共享环境。
