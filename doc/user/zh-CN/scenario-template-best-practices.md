# 场景模板实操指南：从一份文档到能用的助手

> 适用版本：RAGFlow-X v0.6.1｜界面：简体中文｜角色：工作区管理员（`tenant_admin`）或具备「创作」权限的搭建者

这份指南只讲**你在界面上点哪里、会看到什么、看到之后怎么办**。它不解释内部实现，
也不要求你调用接口；文中出现的按钮名、徽章名都是界面上的原文，
术语对照见 §9。看完照着做一遍，大约 10 分钟能拿到一个能问答的助手。

---

## 0. 速查：完整一遍要做的 8 件事

| # | 在哪做 | 做什么 | 做对了会看到 |
|---|---|---|---|
| 1 | 左侧「数据集」 | 新建数据集并上传一篇文档 | 文档出现在列表里 |
| 2 | 数据集详情 →「文档管理」 | 勾选文档 → 点「解析选中」 | 「分块」列从 0 变成 >0 |
| 3 | 左侧「场景模板」 | 选一个和业务相符的场景 | 卡片高亮，右侧出现模板说明 |
| 4 | 向导第 2 步「知识与能力体检」 | 勾选刚建的数据集 → 点「运行能力体检」 | 出现「能力体检结果」，每个库一枚徽章 |
| 5 | 同上 | 看到「可修复项」就按提示修（§4） | 修完重新体检，徽章转「已验证」或仍黄但有解释 |
| 6 | 向导第 3 步「应用形态与配置」 | 填应用名称、选项目、按需选模型 | 「下一步」可点 |
| 7 | 向导第 4 步「验证与创建」 | 看试运行问题与发布检查 → 点「创建应用」 | 提示「应用已创建」，自动跳到应用详情 |
| 8 | 应用详情 /「试跑」 | 用试运行问题问一句 | 有回答，并且能点开引用原文 |

第 1、2 步最关键：**能力体检只回答「你的库够不够格」，它不会替你灌内容。**
库是空的，后面每一步都做不成。

---

## 1. 先准备一个「有内容」的数据集

1. 左侧「数据集」→ 新建，起一个后续能认出来的名字（例如「报销与差旅制度」）。
2. 进数据集 →「文档管理」→「上传文档」。支持 md/pdf/docx/txt 等常见格式。
3. 勾选刚上传的文档 → 点「解析选中」。
4. 等「解析状态」不再变化，并确认「分块」列**大于 0**。

**为什么要盯「分块」这一列**：模板建出来的是「对话/检索应用」，它靠检索文档分块来回答。
分块为 0 时，创建阶段会被上游引擎拒绝（表现为创建失败，提示里带
`doesn't own parsed file` 之类的话）。这一列也是后续「修复」时唯一可靠的进度指示。

`解析` 是异步的，偶尔会弹一次解析失败。**别信一次性的状态**：刷新文档列表，
只要「分块」已经大于 0，就是解析成功了。

---

## 2. 选一个场景

左侧「场景模板」进入的就是向导本身，第一屏是场景卡片列表。

选之前先回答两个问题：

- **我要的是「问答」还是「检索/审阅」？** 卡片上写着支持的应用形态（对话 / 检索 / 助手），
  不支持的形态在第 3 步选不了，界面也会说明「该模板暂不支持直接创建此形态」。
- **我的库能满足它的要求吗？** 第 4 步会告诉你，但先看卡片的示例问题能帮你判断场景是否真的对口。

选错的代价只是重选一次，不会污染数据。平台内置模板**可以直接用**，
不需要先「复制到我的工作区」；只有在你要改模板本身的提示词/参数时，才涉及把模板接管到工作区，
那属于平台管理员的活，不在本指南范围内。

---

## 3. 第 2 步：绑定数据集，跑一次「能力体检」

1. 在「绑定数据集」里勾选 §1 建好的库（至少一个）。
2. 点「运行能力体检」。
3. 右侧出现「能力体检结果」，每个库一张卡片，卡片上是逐项能力与结论徽章。

**徽章只有四种意思**：

| 徽章 | 意思 | 你该怎么做 |
|---|---|---|
| 已验证 | 这项能力就绪 | 不用管 |
| 可修复 | 差一点，界面能直接修 | 按 §4 修，修完重新体检 |
| 未验证 | 探测受限（权限/接口不可用），**不代表通过** | 找管理员确认权限，或换库再试 |
| 阻断 | 这个环境**做不到**这项能力 | 换模板，或换支持的引擎；改配置解决不了 |

三条读法，能挡掉大部分误判：

- **「可修复」不是失败**：它表示模板要的东西你的库差一档，界面上通常有现成的修复按钮。
- **「未验证」不等于「通过」**：系统在拿不到证据时不会替你宣布合格。它也不会阻止你创建，
  但上线后出问题别怪没人提醒。
- **只看「能力体检结果」里带文字的那几行**：`最小等级 → 实际等级` 加一句「系统说明」，
  这句话告诉你差在哪，比徽章更具体。

改完绑定（勾掉/换一个库）或改了应用形态，结论会**自动作废**，需要重新点「运行能力体检」——
不同应用形态要求的必备能力并不相同。

---

## 4. 「应用修复」到底会改什么

「可修复项」下面每条修复都有自己的按钮，按钮旁边会写明它要写入的目标值
（例如「把切分方式改为 book，并按新切分重新解析 12 篇文档」）。点之前必须清楚它属于哪一类：

| 修复项（界面文案） | 它会动的数据 | 你要先确认什么 |
|---|---|---|
| 改用模板要求的切分方式 | 该库的**切分方式**，并**重新解析已有文档** | 已解析的文档会被按新切分重新解析，旧分块被替换 |
| 开启元数据过滤下推并回填元数据（按钮「开启下推并回填」） | 该库的**元数据下推开关**，并开始回填文档元数据 | 回填是异步的，完成后体检才会变绿 |
| 调整该知识库的解析/检索配置 | 不改：向导只给指引，要你去数据集设置里手工调 | 改完回来重新体检 |
| 该能力当前环境不支持 | 不改：引擎能力上限 | 换模板或换引擎 |

### 两个勾选，别混为一谈

如果这个库**正被别的应用使用**，界面会先列出受影响的应用，并要求你勾「我已确认共享影响」。
如果这次修复会**重新解析已有文档**，界面会另外要求你勾「我确认重新解析这 N 篇文档」。

这两件事故意分成两个勾：一个勾不能同时授权两种不同的破坏性写入。

### 点完之后为什么常常还是黄的

因为两件事都是异步的：

- **重新解析**：提交成功只代表任务已入队。界面提示「已提交重新解析；解析完成后请再次运行能力体检」，
  这时候再体检大概率读到「同步中」，不是修复失败。
- **元数据回填**：同理，回填跑完体检才会从「可修复」变「已验证」。

正确节奏是：**点修复 → 看提示 → 等（回到数据集看「分块」/元数据）→ 再点「运行能力体检」**。

如果这个工作区开了审批策略，修复会先提交审批。界面这时提示的是
「该操作已提交审批（工单 …）」，不是「已完成」——批准并生效后再体检。

### 按钮为什么是灰的

按提示补齐就能解锁，常见三种：

- 还没勾「我已确认共享影响」（有别的应用在用它）；
- 还没勾「我确认重新解析这 N 篇文档」（库里有已解析内容）；
- 提示「服务端未给出目标切分方式」——这时需要你到数据集配置里手工改「切分方式」，
  改完回来重新体检（向导宁可不写，也不猜一个值）。

## 5. 第 3 步：应用形态与配置

- **应用名称**：会作为应用名，之后能在列表里搜到。
- **项目**：必填。只有一个项目时会自动选好。
- **应用形态**：模板支持的形态才能选；不支持时界面会解释原因。
- **默认模型**：留空表示用「设置 → 默认模型」里的租户默认；要给这个应用单独指定才填。
- 下面的系统提示词与检索参数由模板给出，界面是只读说明——**不要指望在这里改文案**，
  创建完成后到应用自己的配置里改。

---

## 6. 第 4 步：验证与创建

这一屏把人话版的检查放在一起：

- **试运行问题**：模板自带的问题，创建成功后会自动发起一次试跑（只走检索，不计入发布门禁）。
- **发布检查 / 权限建议 / 预期结果**：告诉你这个场景上线后应该是什么样子、该给谁权限。
- **发布门禁**：说明该模板是否要求「评测通过」才能发布新版本（只影响改模板，不影响创建应用）。

点「创建应用」。三种结果：

| 结果 | 含义 | 下一步 |
|---|---|---|
| 跳到应用详情 / 试跑 | 创建成功 | 用试运行问题问一句，点开引用 |
| 「应用已创建」但试跑失败 | 应用建好了，试跑是附加动作 | 去应用详情手工问一句，不影响应用存在 |
| 「N 个知识库存在硬缺口，创建已被阻止」 | 某个库有「阻断」级能力缺口 | 换模板，或取消绑定该库后重新体检 |

## 7. 上线之后：怎么确认它「真的能用」

创建成功只说明资源建出来了，不等于好用。三条自查：

1. **问一句真问题**：用业务里的真实问法（不是模板给的示例），看答案是否落在你的文档里，
   引用能不能点开原文。答不出来时先看是不是问在了文档没覆盖的范围。
2. **看「试跑」与问答记录**：每次创建会自动发起一次试跑，之后的真实问答也在这里。
   「有记录」比「创建成功」更接近可用。
3. **给能力差距留一条待办**：带差距上线是可以的（「可修复」不阻止创建），但没补齐的能力
   就是将来某类问题答不出来的原因，尤其是「元数据过滤」这类（按部门/年份/合同编号过滤）。
   模板级的健康指标（首次运行完成率、7 日活跃）目前由平台侧通过运维接口查看，界面尚未提供，
   所以日常自查以「有没有人真的在用」为准：实例建出来没人用，和没建是一样的。

## 8. 常见问题（按你看到的提示查）

| 你看到的现象 | 原因 | 怎么做 |
|---|---|---|
| 「当前工作区还没有可用模板」 | 模板按工作区可见，你的工作区还没发布过模板 | 让平台管理员在你要用的工作区里发布模板，或改用有模板的工作区 |
| 能力体检一直转 / 提示失败 | 探针访问上游受限，或引擎暂时不可用 | 稍后重试；仍失败就找管理员看引擎状态，别把它当成「库不合格」 |
| 「未验证」徽章 | 系统拿不到证据（无权限或接口不可用） | 找管理员补权限，或换一个有权限的库 |
| 修复按钮点了没反应（灰色） | 还有确认项没勾，或没有目标值 | 见 §4「按钮为什么是灰的」 |
| 修复后还是「可修复」 | 重新解析/元数据回填还在跑 | 等完成（看「分块」/元数据）再体检，别重复点 |
| 提示「已提交审批（工单 …）」 | 该工作区开了审批策略 | 找审批人批准，生效后再体检 |
| 创建失败、提示里带 `doesn't own parsed file` | 绑定的库里没有已解析内容 | 回到 §1：上传并「解析选中」，确认「分块」>0 |
| 解析时弹过一次失败，但文档看着正常 | 解析是异步批次，接口状态会提前回落 | 以「分块」列 >0 为准，不用重传 |
| 「创建已被阻止」 | 某个库有「阻断」级能力缺口 | 换模板，或取消绑定该库 |
| 想改模板的提示词/参数 | 内置模板归平台管理 | 交给平台管理员；本指南的实操路径不需要改模板 |

## 9. 术语对照：技术文档里的词 ↔ 界面上的词

| 你在别处看到的说法 | 界面/本指南的说法 |
|---|---|
| capability-check / 能力探测 | 「运行能力体检」 |
| requirement / 必备能力 | 体检卡片里的逐项能力（向量、元数据过滤、引用定位…） |
| verdict `satisfied` | 徽章「已验证」/ 结论「通过」 |
| verdict `repairable` | 徽章「可修复」 |
| verdict `probe_limited` | 徽章「未验证」（**不是通过**） |
| verdict `blocked` | 徽章「阻断」（改配置无解） |
| `apply_parse_profile` | 修复项「改用模板要求的切分方式」 |
| `enable_pushdown_and_sync_meta` | 修复项「开启元数据过滤下推并回填元数据」 |
| `reconfigure_dataset` | 修复项「调整该知识库的解析/检索配置」（手工） |
| `instantiate` | 「创建应用」 |
| fork / 基线副本 | 把平台模板接管到工作区改内容；**日常使用不需要**，本指南不涉及 |
| `eval gate` / 发布门禁 | 第 4 步「发布门禁」（只影响改模板并发布新版本） |

需要按接口做事（批量建库、自动化流水线）时，再看运维手册与接口文档；本指南刻意只用界面路径，
因为界面上看不到的东西，用起来最容易出错。
